# rice-eaters 🍚

웹 기반 앱 실험실. **테라포밍 마스 솔로**와 **시나리오별 2~10인 온라인 머더 미스터리**를 하나의 Node.js 서버에서 실행합니다.

## 실행 방법

Node.js **20 이상**이 필요합니다. 패키지 설치는 필요하지 않습니다.

```bash
git pull
node server.js
```

브라우저에서 **http://localhost:3000** 으로 접속하세요.

**Cloudflare 무료 외부 접속:** [DEPLOY_CLOUDFLARE.md](./DEPLOY_CLOUDFLARE.md) — PC에 서버를 켜두고 임시 HTTPS 링크를 무료로 공유합니다. 머더 미스터리는 Quick Tunnel에서 HTTP 폴링으로 동기화됩니다.

**Railway 배포 가이드:** [DEPLOY_RAILWAY.md](./DEPLOY_RAILWAY.md) (대안 호스팅)

- 홈: http://localhost:3000/
- 화성: http://localhost:3000/mars
- 머더 미스터리: http://localhost:3000/mystery
- **머더 미스터리 편집기**: http://localhost:3000/mystery-editor
- 개발 모드(파일 수정 시 재시작): `npm run dev`
- API 통합 테스트: `npm test`

다른 사람은 서버가 실행 중인 컴퓨터의 **LAN IP 주소:3000**으로 접속할 수 있습니다. 예: `http://192.168.0.20:3000/mystery` (주소는 실제 서버 IP로 바꿔주세요.) 방 링크/코드를 공유하면 서로 다른 브라우저에서 같은 게임을 진행합니다. LAN 방화벽에서 3000번 포트 접근을 허용해야 할 수 있습니다. 기본 바인딩은 `0.0.0.0`이고, 포트는 `PORT=4000 npm start` 등으로 변경할 수 있습니다.

**주의:** 현재는 로컬·신뢰 가능한 소규모 네트워크에서 테스트하기 위한 프로토타입입니다. 인터넷에 공개할 경우 HTTPS, 계정 인증, 데이터베이스, 요청 제한 및 운영 보안이 추가로 필요합니다. 공용 서버에 무인증 상태로 직접 노출하지 마세요.

## 서버 저장과 로그

- `data/state.json` — 참가자 세션, 머더 미스터리 방/진행 상태, 화성 개인 저장 데이터 (서버 재시작 후에도 유지)
- `data/activity.jsonl` — 세션 생성, 방문, 방 참가, 페이즈 진행, 캐릭터 선택, 화성 기록 저장 등의 시간순 로그
- 파일은 자동 생성되며 `.gitignore`에 의해 Git 추적에서 제외됩니다. JSON 로그에는 익명 세션 식별자의 일부가 기록되며 실명 계정이나 비밀번호는 아직 없습니다.
- 같은 브라우저의 쿠키로 참가자가 구분됩니다. 다른 브라우저/시크릿 창은 별도 플레이어입니다.
- 화성 진행 상황과 완료 게임 기록은 서버로 저장되며 기존 브라우저 `localStorage` 기록이 발견되면 초기 접속 시 서버로 이전합니다. 브라우저 저장 데이터는 호환성 및 장애 대비용으로 유지합니다. 다른 기기와 화성 저장 내용을 공유하려면 향후 계정/로그인 기능이 필요합니다.

## 머더 미스터리 - 현재 구현

기본 시나리오 **「자정의 저택」** (4인, 더미 콘텐츠):

1. 방장이 시나리오를 선택해 방 생성, 6자리 방 코드/초대 링크 제공
2. 참가자 4명이 모두 온라인이면 방장의 게임 시작 버튼 활성화
3. 시작 후 모든 참여자에게 전체 시놉시스 표시
4. 전원 읽음 확인 후 **방장이 '다음 단계' 버튼을 눌러야** 캐릭터 선택 단계로 이동
5. 4개 더미 캐릭터 중 중복 없이 배역 선택 및 참가자 간 실시간 동기화
6. **전원이 배역을 선택하면 방장이 다음 단계 버튼을 눌러 「캐릭터 숙지」로 이동**
7. 7개 항목으로 구성된 캐릭터별 비공개 책자 (기본·중요·시간대별 행적·소지품·범인 여부·승리 목표·공용 정보)
8. 1층 건물 약도의 **상하좌우/WASD 실시간 캐릭터 이동**, 서버 벽 충돌 검사, 다른 참가자 위치 공개
9. 숙지 완료 버튼으로 준비 상태 공유 후 **방장이 확인하여 1차 조사** 단계 진입
10. 서버 기준 전체 경과 시간/9개 페이즈별 권장 시간(완료 후에도 게임 진행 가능)
11. 지도 메인 화면, I 키로 개인 책자 열기, 챕터 목차/페이지 탐색
12. 2층 저택 계단, 타일 3인 수용, WebRTC 마이크/거리 감쇠·밀담 만장일치
13. 1차 조사: 지도에서 「조사 가능 정보 확인」 버튼을 눌러 카드 갤러리 화면으로 토글. 인당 조사 토큰 4개, 카드 선점 → 토큰 소모 → 자신만 뒷면 확인
14. 선행 카드 해금, 숨겨진 카드, 중복 조사 가능 여부, 자기 카드 금지 설정

**책자 접근 제어:** 참가자 본인에게만 자신의 책자를 전달하며 기본 시나리오 비밀 데이터는 `mystery-content/midnight-manor.js`에 저장합니다. 자신이 조사해 획득한 조사 카드의 뒷면도 본인만 API를 통해 받아볼 수 있습니다.

**조사 단계 규칙:** 카드 선택은 먼저 요청한 사람에게 90초간 예약되며, 본인이 확정하면 토큰 1개가 소비됩니다. 누군가 조사한 카드는 기본적으로 다른 사람이 조사할 수 없습니다. 시나리오별로 중복 조사, 선행 조건, 공개 여부, 특정 배역 조사 금지를 설정할 수 있습니다. 1차 조사의 조사 토큰 4개는 데모값이며 다른 작품에서는 설정을 변경할 수 있습니다.

**지도/밀담:** 데모는 1층+2층을 지원하며 계단 위에 서서 **액션 버튼을 눌러야 층 이동**됩니다. 구역별 색/패턴/경계와 **열쇠로 문 잠금 해제 + 문 열기/닫기**를 지원합니다. 잠금과 개폐 상태는 별도이며, 열린 문만 통과하고 닫힌 문은 이동과 음성을 모두 차단합니다. 한 타일에 최대 3명이 서 있을 수 있습니다. 같은 타일에서 밀담을 시작하거나 참가하려면 관련 인원의 만장일치 동의가 필요합니다. 밀담에서 나가려면 버튼을 누르거나 해당 타일을 벗어나면 됩니다.

**음성:** 마이크와 스피커 버튼은 독립적입니다. 스피커만 켜면 마이크 권한 요청 없이 듣기 전용으로 연결됩니다. 같은 층의 가까운 사람일수록 크게 들리고, 닫힌 문·벽으로 차단된 경로/다른 층/밀담 외 그룹에는 마이크 트랙을 전송하지 않으며 음량도 차단됩니다. 열린 문과 실제 통로를 따라 최단 경로를 계산합니다. 다만 **TURN 중계 서버가 없으므로 다른 집/모바일 망의 NAT 연결이 실패할 수 있습니다.** 실제 음성 품질이나 완전한 방청 방지를 보장하는 상용 구성은 아닙니다.

**현재 구현 범위:** 1차 조사까지. 1차 토론, 2차 조사, 2차 토론·최종 결정, 행동, 결말은 권장 시간 설정만 준비되어 있고 게임 흐름은 미구현입니다. 승점 처리는 수동으로 남겨 두었습니다.

## 머더 미스터리 편집기 및 파일

**/mystery-editor**에서 시놉시스, 인물 공개 프로필/비밀 책자, 범인·승리목표, 조사 카드 앞뒷면, 층별 타일형 지도, 방 색상·패턴·경계, 계단 포털과 문·열쇠 기믹을 디자인할 수 있습니다.

**JSON 내보내기**는 비공개 범인/증거까지 포함하는 `rice-mystery-v1` 원고를 내려받습니다. **JSON 가져오기**로 이전에 저장한 파일을 편집할 수 있습니다. 등록 버튼을 누르면 서버 검증 후 게임 시나리오 선택 목록에 추가되어 친구들과 플레이할 수 있습니다.

발행·원고 열람은 보안상 **서버 PC의 localhost 접속에서만** 가능하며, 등록된 시나리오는 서버의 `data/state.json`에 저장됩니다. **이 파일은 배포 및 PC 교체 전에 백업**하세요. 불러온 시나리오 원고는 플레이어에게 공유하면 안 됩니다.

**구조:** `apps/murder-mystery/`(클라이언트 UI/편집기), `mystery-content/`(기본 스토리 원고·검증기), `server.js`(권한·규칙), `data/state.json`(사용자 제작 시나리오·방 상태)으로 분리했습니다. `mystery-content/`는 웹에서 직접 내려받을 수 없습니다. GitHub 저장소는 별도 비공개 설정이 없으면 저장소 자체의 자료는 공개될 수 있으므로 실제 유료 시나리오에는 비공개 저장소를 권장합니다.

새 스토리·책자·지도·조사 카드 형식: [MYSTERY_STORY_FORMAT.md](./MYSTERY_STORY_FORMAT.md).

## 테스트

```bash
npm test
```

별도 패키지 없이 Node.js의 테스트 러너로 실제 HTTP 4인 방 생성, 연결, 시놉시스 확인, 중복 캐릭터 방지 및 저장 파일/로그를 검사합니다.

기존 화성의 Chromium 스모크 테스트는 Playwright 환경이 준비된 경우 `node tests/mars-browser.cjs`로 실행할 수 있습니다. 기존 게임 규칙·UI 로직은 유지하고 저장 기능에 서버 동기화를 추가했습니다.

## 방장 수동 진행과 독립 음성 조작

- 시놉시스의 전원 읽음, 캐릭터 전원 선택, 캐릭터 책자 전원 숙지는 **준비 표시만** 합니다. 다음 단계 이동은 방장이 진행 버튼을 누를 때만 발생하며 서버에서 해당 권한·전원 준비를 검증합니다.
- 방장은 준비가 끝나면 방 상단의 **방장 · 다음 단계** 버튼을 사용할 수 있습니다. 1차 조사 이후 페이즈는 아직 미구현입니다.
- **🎙 마이크 켜기/끄기**는 내 소리를 다른 사람에게 보내는지 결정하며, **🔊 스피커 켜기/끄기**는 다른 사람의 소리를 듣는지 결정합니다. 서로 영향을 주지 않습니다.
- 닫힌 문과 벽이 음성 경로를 막습니다. 열린 통로가 다른 방향으로 연결되어 있다면 해당 길이를 따라 거리가 길어진 만큼 음량이 감소할 수 있습니다. 밀담은 기존처럼 승인된 상대방에게만 내 마이크 트랙이 전달됩니다.
- 마이크를 켰다고 스피커가 자동으로 켜지거나, 스피커를 켰다고 마이크 사용 권한을 요청하지 않습니다.
