# rice-eaters 🍚

웹 기반 앱 실험실. **테라포밍 마스 솔로**와 **시나리오별 2~10인 온라인 머더 미스터리**를 하나의 Node.js 서버에서 실행합니다.

## 실행 방법

Node.js **20 이상**이 필요합니다. 패키지 설치는 필요하지 않습니다.

```bash
git pull
node server.js
```

브라우저에서 **http://localhost:3000** 으로 접속하세요.

**Cloudflare 무료 외부 접속:** [DEPLOY_CLOUDFLARE.md](./DEPLOY_CLOUDFLARE.md) — PC에 서버를 켜두고 임시 HTTPS 링크를 무료로 공유합니다. 머더 미스터리는 Quick Tunnel에서 HTTP 폴링으로 동기화됩니다.

**Railway 배포 가이드:** [DEPLOY_RAILWAY.md](./DEPLOY_RAILWAY.md) (대안 호스팅)

- 홈: http://localhost:3000/
- 화성: http://localhost:3000/mars
- 머더 미스터리: http://localhost:3000/mystery
- **머더 미스터리 편집기**: http://localhost:3000/mystery-editor
- 개발 모드(파일 수정 시 재시작): `npm run dev`
- API 통합 테스트: `npm test`

다른 사람은 서버가 실행 중인 컴퓨터의 **LAN IP 주소:3000**으로 접속할 수 있습니다. 예: `http://192.168.0.20:3000/mystery` (주소는 실제 서버 IP로 바꿔주세요.) 방 링크/코드를 공유하면 서로 다른 브라우저에서 같은 게임을 진행합니다. LAN 방화벽에서 3000번 포트 접근을 허용해야 할 수 있습니다. 기본 바인딩은 `0.0.0.0`이고, 포트는 `PORT=4000 npm start` 등으로 변경할 수 있습니다.

**주의:** 현재는 로컬·신뢰 가능한 소규모 네트워크에서 테스트하기 위한 프로토타입입니다. 인터넷에 공개할 경우 HTTPS, 계정 인증, 데이터베이스, 요청 제한 및 운영 보안이 추가로 필요합니다. 공용 서버에 무인증 상태로 직접 노출하지 마세요.

## 서버 저장과 로그

- `data/state.json` — 참가자 세션, 머더 미스터리 방/진행 상태, 화성 개인 저장 데이터 (서버 재시작 후에도 유지)
- `data/activity.jsonl` — 세션 생성, 방문, 방 참가, 페이즈 진행, 캐릭터 선택, 화성 기록 저장 등의 시간순 로그
- 파일은 자동 생성되며 `.gitignore`에 의해 Git 추적에서 제외됩니다. JSON 로그에는 익명 세션 식별자의 일부가 기록되며 실명 계정이나 비밀번호는 아직 없습니다.
- 같은 브라우저의 쿠키로 참가자가 구분됩니다. 다른 브라우저/시크릿 창은 별도 플레이어입니다.
- 화성 진행 상황과 완료 게임 기록은 서버로 저장되며 기존 브라우저 `localStorage` 기록이 발견되면 초기 접속 시 서버로 이전합니다. 브라우저 저장 데이터는 호환성 및 장애 대비용으로 유지합니다. 다른 기기와 화성 저장 내용을 공유하려면 향후 계정/로그인 기능이 필요합니다.

## 머더 미스터리 - 현재 구현

기본 시나리오 **「자정의 저택」** (4인, 더미 콘텐츠):

1. 방장이 시나리오를 선택해 방 생성, 6자리 방 코드/초대 링크 제공
2. 참가자 4명이 모두 온라인이면 방장의 게임 시작 버튼 활성화
3. 시작 후 모든 참여자에게 전체 시놉시스 표시
4. 전원이 읽음을 확인하면 **방장이 다음 단계 버튼으로 캐릭터 선택 진행**
5. 4개 더미 캐릭터 중 중복 없이 배역 선택 및 참가자 간 실시간 동기화
6. **전원이 배역을 선택해도 방장이 진행 버튼을 눌러야 캐릭터 숙지 진입**
7. 7개 항목으로 구성된 캐릭터별 비공개 책자 (기본·중요·시간대별 행적·소지품·범인 여부·승리 목표·공용 정보)
8. 1층 건물 약도의 **상하좌우/WASD 실시간 캐릭터 이동**, 서버 벽 충돌 검사, 다른 참가자 위치 공개
9. 모두 숙지 완료 시 **방장이 1차 조사 시작 버튼으로 진행**
10. 서버 기준 전체 경과 시간/9개 페이즈별 권장 시간(완료 후에도 게임 진행 가능)
11. 지도 메인 화면, I 키로 책자 전환 / R 키로 조사 카드 전용 화면 전환
12. 2층 저택 계단, 타일 3인 수용, WebRTC 마이크/거리 감쇠·밀담 만장일치
13. 1차 조사: 인당 조사 토큰 4개, 정보 카드 선점 → 토큰 소모 → 자신만 카드 뒷면 확인
14. 선행 카드 해금, 숨겨진 카드, 중복 조사 가능 여부, 자기 카드 금지 설정

**책자 접근 제어:** 참가자 본인에게만 자신의 책자를 전달하며 기본 시나리오 비밀 데이터는 `mystery-content/midnight-manor.js`에 저장합니다. 자신이 조사해 획득한 조사 카드의 뒷면도 본인만 API를 통해 받아볼 수 있습니다.

**방장 전용 진행:** 시놉시스 → 캐릭터 선택 → 캐릭터 숙지 → 1차 조사는 전원의 준비가 끝난 후 방장 버튼으로만 넘어갑니다. 준비가 덜 됐거나 아직 구현되지 않은 이후 단계에는 진행할 수 없습니다.

**조사 단계 규칙:** 카드 선택은 먼저 요청한 사람에게 90초간 예약되며, 본인이 확정하면 토큰 1개가 소비됩니다. 누군가 조사한 카드는 기본적으로 다른 사람이 조사할 수 없습니다. 시나리오별로 중복 조사, 선행 조건, 공개 여부, 특정 배역 조사 금지를 설정할 수 있습니다. 1차 조사의 조사 토큰 4개는 데모값이며 다른 작품에서는 설정을 변경할 수 있습니다.

**지도/밀담:** 잠긴 문·닫힌 문·열린 문 상태를 별도로 관리하고 열기/닫기 액션을 제공합니다. 데모는 1층+2층을 지원하며 계단 위에 서서 **액션 버튼을 눌러야 층 이동**됩니다. 구역별 색/패턴/경계 표시와 **열쇠로 잠긴 문 열기** 기능이 있으며, 한 타일에 최대 3명이 서 있을 수 있습니다. 같은 타일에서 밀담을 시작하거나 참가하려면 관련 인원의 만장일치 동의가 필요합니다. 밀담에서 나가려면 버튼을 누르거나 해당 타일을 벗어나면 됩니다.

**음성:** 마이크와 스피커를 각각 독립적으로 ON/OFF 할 수 있습니다. 닫힌 문과 벽은 음성 경로를 차단합니다. 마이크 권한 동의 후 WebRTC P2P 통화가 연결됩니다. 같은 층의 가까운 사람일수록 크게 들리고 다른 층이나 밀담 외 그룹은 음소거/트랙 전송 차단됩니다. 다만 **TURN 중계 서버가 없으므로 다른 집/모바일 망의 NAT 연결이 실패할 수 있습니다.** 실제 음성 품질이나 완전한 방청 방지를 보장하는 상용 구성은 아닙니다.

**현재 구현 범위:** 1차 조사까지. 1차 토론, 2차 조사, 2차 토론·최종 결정, 행동, 결말은 권장 시간 설정만 준비되어 있고 게임 흐름은 미구현입니다. 승점 처리는 수동으로 남겨 두었습니다.

## 머더 미스터리 편집기 및 파일

**/mystery-editor**에서 시놉시스, 인물 공개 프로필/비밀 책자, 범인·승리목표, 조사 카드 앞뒷면, 층별 타일형 지도, 방 색상·패턴·경계, 계단 포털과 문·열쇠 기믹을 디자인할 수 있습니다.

**JSON 내보내기**는 비공개 범인/증거까지 포함하는 `rice-mystery-v1` 원고를 내려받습니다. **JSON 가져오기**로 이전에 저장한 파일을 편집할 수 있습니다. 등록 버튼을 누르면 서버 검증 후 게임 시나리오 선택 목록에 추가되어 친구들과 플레이할 수 있습니다.

발행·원고 열람은 보안상 **서버 PC의 localhost 접속에서만** 가능하며, 등록된 시나리오는 서버의 `data/state.json`에 저장됩니다. **이 파일은 배포 및 PC 교체 전에 백업**하세요. 불러온 시나리오 원고는 플레이어에게 공유하면 안 됩니다.

**구조:** `apps/murder-mystery/`(클라이언트 UI/편집기), `mystery-content/`(기본 스토리 원고·검증기), `server.js`(권한·규칙), `data/state.json`(사용자 제작 시나리오·방 상태)으로 분리했습니다. `mystery-content/`는 웹에서 직접 내려받을 수 없습니다. GitHub 저장소는 별도 비공개 설정이 없으면 저장소 자체의 자료는 공개될 수 있으므로 실제 유료 시나리오에는 비공개 저장소를 권장합니다.

새 스토리·책자·지도·조사 카드 형식: [MYSTERY_STORY_FORMAT.md](./MYSTERY_STORY_FORMAT.md).

## 테스트

```bash
npm test
```

별도 패키지 없이 Node.js의 테스트 러너로 실제 HTTP 4인 방 생성, 연결, 시놉시스 확인, 중복 캐릭터 방지 및 저장 파일/로그를 검사합니다.

기존 화성의 Chromium 스모크 테스트는 Playwright 환경이 준비된 경우 `node tests/mars-browser.cjs`로 실행할 수 있습니다. 기존 게임 규칙·UI 로직은 유지하고 저장 기능에 서버 동기화를 추가했습니다.

## 조사 카드 공개·양도 및 2차 조사 (2026-11)

- **내가 보유한 조사 카드**: 조사 토큰을 소모해 카드를 조사하면 카드의 뒷면을 본인만 확인할 수 있고, 카드 한 장을 개인 소유하게 됩니다. 기존에 플레이하던 방도 첫 조회 시 과거 조사 기록에서 소유권을 복원합니다.
- **전체 공개**: 보유 카드에서 전체 공개 버튼을 누르면 모든 방 참가자에게 카드 뒷면이 영구 공개됩니다. 서버에 공개 기록이 남고 취소할 수 없습니다. 카드가 다른 사람에게 양도되어도 공개는 유지됩니다.
- **선택 공개**: 같은 지도 칸의 플레이어를 선택하여 해당 카드의 뒷면을 보여줍니다. 둘 중 한 명이 다른 칸으로 이동하는 즉시 정보 공개가 종료되며, 다시 같은 칸으로 돌아와도 이전 선택 공개가 자동으로 되살아나지는 않습니다.
- **카드 양도**: 카드의 `transferable`이 true인 경우 같은 타일 참가자에게 제안할 수 있습니다. 상대방이 수락해야만 카드 소유권이 이전되고, 그 뒤부터 새 소유자만 비공개 카드를 볼 수 있습니다. 카드마다 양도를 금지할 수 있습니다. 제안은 90초 후 만료되며, 어느 쪽이든 이동하면 취소됩니다.
- **조사 토큰 양도**: 같은 타일에서 수량을 지정하여 제안하고, 수령자가 수락해야만 토큰이 이동합니다. 제안 단계에는 토큰이 차감되지 않고, 수락 시점에도 잔액을 서버에서 검사합니다.
- **후속 단계 동의**: 1차 조사부터 단계별 참가자 전원의 **「다음 단계로 넘어가기 동의」**가 모인 경우에만 방장에게 다음 단계 버튼이 활성화됩니다. 언제든 동의를 철회할 수 있습니다. 단계별 권장 타이머를 초과하지 않았어도 진행할 수 있으며, 새 단계로 이동하면 동의 상태가 초기화됩니다.
- **2차 조사**: 1차 조사에서 얻은 카드와 잔여 조사 토큰, 전체 공개 상태를 유지합니다. 시나리오에 설정된 `tokensPerSecondInvestigation`만큼 추가 토큰이 지급됩니다(기본 4개). 조사 카드 선점과 뒷면 공개, 카드·토큰 교환을 동일하게 지원합니다.
- **단계 구분**: 1차 토론·2차 토론·행동·결말의 단계 이동 및 지도·음성·개인 책자 접근은 지원하지만, 최종 투표/점수 판정 등 시나리오별 토론·결말 세부 규칙은 아직 구현하지 않았습니다.

보유 조사 카드는 조사 화면에서 확인합니다. **「조사 가능 정보 확인」(R 키)** → **「내가 보유한 조사 카드」**에서 전체 공개·선택 공개·카드 양도·토큰 양도를 실행합니다. 서버 원본 데이터는 `data/state.json`에 저장되므로 기존처럼 백업하세요.

## 신규 정식 시나리오 — D1 사옥: 왕좌의 마지막 한 수

머더 미스터리 게임에서 **D1 사옥: 왕좌의 마지막 한 수**를 선택할 수 있습니다. 다섯 명의 합숙 초청생(조비, 마유시, 차지우, 하수, 감독 맥)과 상주자 두 명(매니저 카알, 요리사 클라우드)으로 구성된 **7인용** 사건입니다. NPC인 배익호는 살해된 피해자입니다.

- **게임 데이터:** `mystery-content/d1-gaming.case.json` (단일 편집 가능한 `rice-mystery-v1` JSON)
- **제작자 설명/스포일러:** `mystery-content/D1_AUTHOR_GUIDE.md`
- **개인 소지품 조사 카드:** 등장인물당 4장 × 7명 = 28장
- **추가 조사 카드:** 교단 12장, 당일 행적 12장, 실제 살인 증거·트릭 19장 = 43장
- **총 카드:** 71장. 토큰은 개인별 1차 4개 + 2차 4개, **총 발행 56개**.
- 2차에서만 해금되는 카드 21장, 일부는 카드 제목까지 감춰져 있고 일부는 실제 현장 타일에서만 조사할 수 있습니다.
- 4층짜리 D1 사옥: 1층 로비·주방, 2층 강의실·숙소, 3층 서버·장비실, 4층 왕좌실·전시실·봉인 보관실.

## 캐릭터 일러스트 · 조사 카드 그림 · 지도 가구 오브젝트

기본 제공되는 네 개 시나리오 모두 캐릭터 선택 화면과 책자에 **배역별 SVG 초상화**를, 조사 카드 앞면/뒷면 보기 영역과 소지품 페이지에 **주제별 SVG 조사 일러스트**를 표시합니다. 해당 그림은 브라우저에서 로컬 생성하는 벡터 도형이며 별도 네트워크 다운로드가 필요하지 않습니다. 한글 이름/캐릭터 ID 및 시나리오별 색상으로 시각적 차이를 만듭니다.

각 층의 `objects` 배열에는 장식용 가구를 배치했습니다. **D1 사옥에는 주방 싱크대·냉장고·조리대, 2층 연습실 PC, 4층 가고일 석상·왕좌**가 있고, 다른 사건에도 연애 촬영 카메라·선착장 보트, SF 기억 포드·서버 랙, 학교 망원경·투영기·책장을 추가했습니다. 총 **65개 오브젝트**가 네 사건의 지도에 들어갑니다.

- `mystery-content/*.case.json`: 각 층 `game.floors[].objects` 배열에 `id`, `kind`, `name`, `x`, `y`, `solid` 및 선택적 `icon`을 지정합니다.
- `solid: false`: 배경 장식이며 이동이 가능합니다(네 기본 사건의 오브젝트 기본값).
- `solid: true`: 서버가 해당 타일로의 이동을 차단합니다. 문·계단 위에 통과 불가 가구를 배치할 수 없습니다.
- `apps/murder-mystery/illustrations.js`: 벡터 초상화·조사 카드 아트·지도 아이콘 렌더러입니다.
- `/mystery-editor`: 지도 편집기의 **가구·장식 오브젝트** 브러시로 추가/교체/삭제하고 오브젝트의 종류·이름·충돌 옵션을 관리할 수 있습니다.

**참고:** 최초에 생성한 콘셉트 보드의 픽셀 이미지를 직접 잘라 넣은 것이 아니라, 코드에서 곧바로 표시 가능한 새 SVG 벡터 일러스트를 사용한 단계입니다. 콘셉트 보드 원본 PNG를 실제 게임용 고해상도 아트 파일로 별도 교체하려면 개별 에셋 업로드가 필요합니다.
