# 멀티플레이 기능 점검용 더미 사건

시나리오 목록에서 **[테스트 전용] 바나나 서버 실종 사건**을 선택하고 새 방의 정원을 3~7명 중 고릅니다. 일반 게임용 콘텐츠가 아니며 진범은 항상 테스터 1입니다. 선택한 정원만큼 배역과 소지품이 열립니다. 기존 시나리오의 정원은 바뀌지 않습니다.

## 점검 순서

1. 서로 다른 브라우저 프로필/기기로 참가합니다. 일반 탭끼리는 세션을 공유하므로 참가자 수를 늘리지 못합니다. 초대 코드, 정원 초과 차단, 온라인 표시와 방장 퇴장 시 권한 이전을 확인합니다.
2. 방장이 시작합니다. 시놉시스 확인, 배역 선택, 캐릭터 숙지를 마친 뒤에도 방장이 다음 단계를 눌러야 진행되는지 확인합니다.
3. 지도에서 화살표 이동, E 주변 선택, F 선택 실행, Esc 닫기를 확인합니다. 1층 중앙 문은 열고 닫을 수 있습니다. 서쪽 테스트실의 첫 장소 카드에서 2층 중앙 문의 테스트 열쇠를 얻습니다. (1,5)의 계단은 이동 액션으로 사용합니다.
4. 조사 카드는 소지품 28장과 장소 카드 16장입니다. 같은 사람의 소지품과 같은 장소는 각 조사 단계에서 1장씩 조사할 수 있습니다. 다른 참가자에게 다음 카드를 맡기고 2차 조사 해금을 확인합니다.
5. 같은 타일에서 선택 공개와 양도 제안/승인/거절을 시험합니다. 제안만으로 비공개 뒷면이 노출되면 안 됩니다. 이동하면 선택 공개와 대기 중인 교환이 해제되어야 합니다. 전체 공개는 남아 있어야 합니다. 토큰 양도도 시험할 수 있습니다.
6. 같은 타일의 두 참가자가 밀담을 요청하고 동의합니다. 마이크/스피커를 각각 켜고 끄며 실제 음성을 점검합니다. 멀리 이동하거나 다른 층으로 이동해 공간 음성과 밀담 종료를 확인합니다.
7. 단계 진행 동의와 방장의 다음 단계를 확인합니다. 최종 결정에서 방장이 테스터 1을 구속/해제해 공통 결말 분기를 확인합니다. 행동 단계에는 보호·공개·탈출·제압·공격용 테스트 능력이 있고 패스할 수도 있습니다.
8. 결말에서 개인 목표 달성/실패, 사망/구속/제압/탈출/생존 판정을 바꿔 개인 결말과 공통 결말을 확인합니다. 새로고침 후 정원과 진행 상태가 유지되는지도 확인합니다.

## 자동 검증 범위

`tests/multiplayer-test-case.test.cjs`는 3·4·5·6·7인 각각 독립 HTTP 세션으로 방 입장부터 결말까지 실제 서버 API를 호출합니다. 공개/비공개 권한, 양도 동의, 밀담 합의, 조사 제한, 2차 해금, 방장 권한, 활성 배역 수, 행동 순서와 저장을 검사합니다. 3인 흐름에서는 문, 계단과 열쇠 잠금 해제도 검사합니다.

실제 마이크 장치, 기기 간 오디오 품질과 외부 네트워크의 WebRTC 연결은 위 수동 절차로 확인해야 합니다.
