# 모션 아틀리에

기존 Node 서버에서 `/live2d`를 엽니다. 별도 npm 의존성은 없습니다.

## 생성과 연결

웹 화면의 **AI API 연결**에서 OpenAI 이미지 API 키와 모델 ID를 입력합니다. 기본 모델은 `gpt-image-2.5-flare`이며, 운영자가 `.env`의 `LIVE2D_IMAGE_MODEL`로 변경할 수 있습니다. 연결 시 `/models/{id}`로 접근 권한을 검사합니다. 생성 시 `/images/generations`를 한 번 호출해 **16파츠 투명 PNG 아틀라스**를 받습니다. `background: transparent`, `output_format: png`, `b64_json` 응답이 필요합니다. 권한·잔액·투명 PNG 지원 여부는 실제 사용 계정과 모델에 따라 달라집니다.

호환 API를 운영하는 경우 `.env`에 `LIVE2D_AI_BASE_URL=https://example.com/v1`을 설정합니다. 브라우저에서 임의 서버 주소를 받지 않습니다. 실제 연결 주소는 키 입력 화면에 표시합니다. 키는 서버 메모리에서 세션별로 1시간 보관하고, 연결 해제·서버 재시작 시 삭제합니다. 진행 중인 호출은 연결 해제로 취소되지 않습니다. 브라우저 저장소·프로젝트·ZIP에는 키를 넣지 않습니다. 외부 접속 시 HTTPS가 필요합니다.

작업은 세션 쿠키로 분리하며 `DATA_DIR/live2d/<session-hash>/<job-id>`에 저장합니다. 같은 브라우저 세션에서 새로고침해도 작업 결과를 불러옵니다. 쿠키를 삭제하면 기존 결과에 접근할 수 없습니다. 생성은 세션당 1개, 서버 전체 2개 동시 실행, 세션당 20개 저장으로 제한합니다. 프롬프트와 생성 결과는 서버에 저장되며, 서버 운영자는 이 파일에 접근할 수 있습니다.

## 실제 생성 범위

아틀라스의 각 셀에서 알파 영역을 분석하고 16개 독립 메시를 조립합니다. JS 바이너리 작성기가 실제 Cubism 4.0 호환 `.moc3`를 생성합니다. 파라미터 키폼에 정점 변형·불투명도를 기록하며, 고개 XYZ·눈 깜빡임·눈썹·입 벌리기·입 모양·몸 회전·호흡·머리카락의 **13개 파라미터**를 제공합니다. PNG를 `.moc3`로 이름만 바꾸지 않습니다.

브라우저는 Purism Core에서 모델을 평가한 좌표를 WebGL로 그립니다. 모델·물리 파일은 ZIP 안에 포함됩니다. 브라우저의 자동 움직임은 미리보기용 파라미터 드라이버이며 VTube Studio의 카메라 추적과 동일한 알고리즘은 아닙니다. VTube Studio에서는 자체 추적·물리 런타임을 사용합니다.

자동 리깅 **초안**으로, 파츠의 비율·경계·눈 감김 모양 등은 수작업 수준에 미치지 못할 수 있습니다. 파츠 배치를 수정하고 MOC3를 다시 생성할 수 있습니다. 독립 눈동자, 깊은 3D 회전, 손·전신 리깅, 클리핑 마스크, PSD·Cubism Editor `.cmo3`는 포함하지 않습니다. AI가 4×4 파츠 배치를 지키지 못하면 실패 또는 조립 오류가 발생할 수 있습니다. 투명 배경·빈 파츠·런타임 검증 실패는 성공으로 표시하지 않습니다.

## 내보내기와 검증

ZIP에는 `.moc3`, `.model3.json`, `.physics3.json`, `.cdi3.json`, 표정, 텍스처, `project.json`, 런타임 검증 결과가 포함됩니다. 압축을 풀어 모델 폴더 전체를 VTube Studio의 `Live2DModels`에 복사하고 자동 설정을 실행합니다. `.vtube.json`은 VTube Studio가 직접 만듭니다.

샘플 **Lumi / 루미**는 이 앱을 위해 생성한 오리지널 캐릭터입니다. 16파츠 중 중복 리본을 숨겨 15메시를 표시합니다. Purism Core와 공식 Cubism Core 5.1에서 `.moc3`를 읽고 모든 파라미터의 정점·불투명도 반응을 확인했습니다. 공식 Core는 검증 환경에서만 사용하며 재배포하지 않습니다. **Steam VTube Studio 실행 테스트는 미실시**입니다. 사용자 API 키를 사용한 유료 이미지 호출도 자동 테스트에 포함하지 않습니다. 테스트는 이미지 API 응답을 모의하고 그 이후 실제 컴파일·런타임·ZIP·세션 분리를 검증합니다.

`node --test tests/live2d.test.cjs` / CI Chrome: `node tests/live2d-browser.cjs`

## 시즈쿠·하루토 Live2D 리워크

`/live2d?sample=shizuku`, `/live2d?sample=haruto`에서 두 캐릭터를 바로 엽니다. 샘플 선택 메뉴에서도 전환할 수 있고, API 연결 없이 모델을 조작·다운로드할 수 있습니다. 시즈쿠는 긴 헝클어진 머리·안경·회색 트레이닝복의 성인 여성, 하루토는 올린 머리·탄탄한 체격·단정한 교복의 성인 남성 디자인입니다.

원화를 참조해 새 투명 파츠 아틀라스를 제작했습니다. 얼굴·귀·코·머리카락을 하나의 일관된 원화 메시로 유지하고, 눈을 뜬 파츠와 감은 파츠·눈썹·입을 분리했습니다. 전체 머리 변형을 공유하므로 얼굴 파츠를 서로 다른 방식으로 움직이지 않습니다. 머리카락 변형은 얼굴 영역 밖에 적용하며, 몸은 목 아래에 움직임을 배치합니다. 남자 캐릭터의 목 중복을 줄이기 위해 머리 메시의 아래 경계를 턱 윤곽에 맞춥니다. 여자 캐릭터는 긴 머리 안의 얼굴·목 비율을 맞추는 세로 좌표 매핑을 사용합니다.

각 모델은 12개 원화 셀 중 10개 메시를 사용하며, 실제 MOC3에 13개 파라미터를 기록합니다. 프로젝트 형식은 `rice-live2d-portrait-v2`입니다. 이 두 샘플의 배치는 읽기 전용이고 기존 16파츠 AI 생성기의 배치 편집 경로를 바꾸지 않습니다. 깊은 3D 회전·독립 눈동자·손 리깅은 포함하지 않습니다. 작은 고개 움직임과 깜빡임·말하기·호흡용 모델입니다.

`node scripts/build-live2d-samples.cjs <ZIP출력폴더>`로 아틀라스에서 모델을 다시 생성합니다. 검증용 공식 Core가 로컬에 있는 경우에만 `LIVE2D_QA_CORE_PATH`를 설정해 추가 검증할 수 있습니다. 공식 Core 파일 자체는 저장소나 ZIP에 재배포하지 않습니다. 현재 모델 2종 모두 공식 Cubism Core 5.1에서 파일 로딩과 13개 파라미터 반응을 검증했습니다. **Steam VTube Studio 직접 실행·카메라 추적 테스트는 미실시**입니다.


## 추가 VTuber 모델 3종

- **미엘 / Miel** (`?sample=miel`): 복숭아빛 단발, 고양이 귀, 민트색 눈과 크림색 카디건의 포근한 카페 캐릭터.
- **나리 / Nari** (`?sample=nari`): 남보라색 단발과 작은 땋은 머리, 별 장식 베레모, 라벤더 케이프의 중성적인 별빛 사서.
- **루리 / Ruri** (`?sample=ruri`): 코랄색 짧은 양갈래와 청록색 눈, 바다색 재킷과 나침반 장식의 활발한 탐험가.

모두 성인 오리지널 캐릭터입니다. 초기 버전은 분리 파츠로 제작했으며, 현재 아래 v3 방식으로 교체했습니다. 유명 VTuber들의 친근한 표정, 선명한 색과 알아보기 쉬운 실루엣을 참고한 디자인 방향입니다. 각 모델은 실제 MOC3·모델 설정·텍스처·물리·표정을 포함하며, 현재 v3는 공식 Cubism Core 5.1과 웹 런타임에서 11개 파라미터를 검증합니다. Steam VTube Studio 직접 실행 테스트는 미실시입니다.

특정 모델만 다시 생성하려면 `node scripts/build-live2d-samples.cjs <ZIP출력폴더> miel,nari,ruri`를 사용합니다. 작은 고개 움직임·눈 깜빡임·말하기·호흡용 기본 리깅입니다.

추가 3종은 입 벌리기 0·0.2·1에 별도 키폼을 두어 발화 중 열린 입이 투명해지거나 닫힌 입이 겹쳐 남는 현상을 줄였습니다.


## 얼굴 배치를 보존하는 v3 (미엘·나리·루리)

이전 파츠 조립에서 눈·입의 크기와 위치, 얼굴과 앞머리의 관계가 깨지는 문제가 있었습니다. 최신 3종은 얼굴·앞머리·목·몸이 완성된 한 장의 원화를 기준으로 다시 제작했습니다. 기본 표정에서는 원화의 모든 얼굴 요소를 같은 원본 픽셀 좌표에 유지합니다. 눈·입 이미지를 따로 생성해 얼굴 빈칸에 배치하지 않습니다.

원화에서 눈 감김과 말하기 표정을 수정한 뒤, 눈·입을 제외한 머리의 특징점으로 표정 이미지를 원화에 정렬합니다. 현재 3종의 정렬 오차 중앙값은 1픽셀 미만이며, 큰 배율·위치 변화나 피부/머리카락 경계 불일치는 빌드 실패로 처리합니다. 표정 영역은 주변 피부·앞머리까지 포함하는 패치이며, 원본과 같은 좌표·같은 픽셀 크기로 겹칩니다. 기본 표정에서 패치는 보이지 않습니다. 중립 얼굴의 위치를 다시 설계하거나 개별 눈·코·입을 늘려 붙이는 단계가 없습니다.

공간상 메시 경계를 나누더라도 원본 그림의 좌표는 그대로이고, 맞닿은 정점은 공통 변형을 적용합니다. 얼굴 중앙의 앞머리는 별도 흔들림을 적용하지 않습니다. 머리 회전은 목 아래에서 연속적으로 줄어들어 머리·목·몸 사이에 절단면이 벌어지지 않도록 합니다. 11개 파라미터를 제공하며, 독립 눈썹 파츠를 제거하고 그려진 눈썹을 보존합니다. 독립 눈동자 추적, 큰 3D 회전, cmo3 편집 프로젝트는 제공하지 않습니다.

웹 화면의 **원화와 비교**로 기준 그림과 기본 모델을 전환할 수 있습니다. 이 비교는 모델을 기본 표정으로 돌리고 자동 움직임을 멈춥니다. 브라우저 검사는 실제 WebGL 모델과 원화의 렌더링 픽셀 차이도 확인합니다. 이 검사는 얼굴이 예쁜지를 자동 판정하는 검사가 아니라, 검수한 원화의 얼굴 배치가 모델에서 다시 깨지는 것을 방지하기 위한 검사입니다.

이미 생성된 v3를 다시 컴파일: `node scripts/build-registered-models.cjs <ZIP출력폴더> miel,nari,ruri` (Node만 필요).

새 원화·표정 이미지에서 준비: `python scripts/prepare-registered-portrait.py miel <master.png·blink.png·talk.png가 있는 폴더> apps/live2d-studio/assets/samples/miel`. 이 제작 단계에만 Pillow, numpy, opencv-python-headless가 필요합니다. 배포된 웹 서버는 Python이나 OpenCV 없이 실행됩니다. PNG 아틀라스의 기준 원화 영역은 원본 RGBA 해시로 검증하며, 개별 표정 패치가 확대·축소되지 않았는지도 검사합니다.

이번 변경은 검수한 샘플 3종의 제작 경로를 교체한 것입니다. 사용자 API 키를 사용하는 일반 16파츠 자동 생성기는 기존 동작을 유지하며, 같은 품질을 보장하는 것으로 표시하지 않습니다. 시즈쿠·하루토·루미는 이전 제작 방식의 샘플입니다. Steam VTube Studio 직접 실행 검증은 여전히 미실시입니다.

확인한 공식 시각 자료: [호쇼 마린 공식 캐릭터 이미지](https://hololive.hololivepro.com/talents/houshou-marine/), [텐코 시부키 공식 캐릭터 이미지](https://stellive.me/shibuki). 참고 이미지는 저장소나 모델 패키지에 포함하지 않습니다.

## 동작별 확인과 메시 원본 편집

미리보기 아래 **고개 좌우 / 표정·입 모양 / 깜빡임 / 말하기**는 다른 자동 움직임을 멈추고 선택한 파라미터만 6초 주기로 재생합니다. 고개 좌우는 ParamAngleX만, 표정은 기존 Smile의 ParamMouthForm만, 깜빡임은 양쪽 EyeOpen만, 말하기는 MouthOpenY만 사용합니다. 음성·웹캠을 입력하거나 Steam VTube Studio를 실행하는 기능은 아닙니다. 현재 v3의 좌우는 작은 2D 이동·압축이며 옆얼굴이 드러나는 회전은 없습니다. 표정은 입 모양만 변하고 감정별 눈썹·눈·볼 표정은 없습니다.

**현재 v3는 뚜따용 완성 모델이 아닙니다.** Portrait_* 메시들은 그림을 공간별로 나눈 영역이며 얼굴·앞머리·옷 같은 해부학적/의상별 파츠가 아닙니다. 눈 감김·말하기는 주변 피부까지 포함한 패치입니다. 가려진 이마·흰자·목·몸을 그려 넣은 PSD, 독립 눈동자/눈꺼풀/입술, 머리·몸 교체용 디포머, 편집용 cmo3는 없습니다.

파츠 배치 탭의 **실제 메시 원본 ZIP**은 미엘·나리·루리의 실제 메시별 투명 PNG, 원본 픽셀 좌표, 고유 ID, 중립 메시 정점/UV/삼각형, 파라미터 연결, project.json과 registration.json을 내보냅니다. manifest.json은 위 지원 여부를 false로 기록합니다. PNG로 나눠 내보냈다는 이유로 Cubism 파츠 분리를 완료했다고 표시하지 않습니다.

- 내보내기: `node scripts/live2d-authoring.cjs export miel Miel-mesh-source.zip`
- ZIP을 풀어 PNG를 같은 크기·같은 위치로 수정한 뒤: `node scripts/live2d-authoring.cjs repack <원본폴더> <별도출력폴더>`

재패킹은 텍스처와 MOC3를 새로 만들고 런타임에서 파라미터를 검증합니다. bundled 샘플은 덮어쓰지 않습니다. 이 경로는 프로젝트 전용 소스 편집이며 Cubism Editor 편집 프로젝트를 대신하지 않습니다. 독립 파츠와 가려진 면을 복원하는 재제작이 있어야 머리·몸·옷의 자유로운 교체가 가능합니다.
